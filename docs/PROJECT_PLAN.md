---

## 1. فكرة المشروع

تطبيق لمدرسة أفضل العلوم يحفظ لكل طالب تلاواته المسجّلة في استوديو المدرسة، مع ملاحظات معلمه عليها، ويسمح للطالب بتسجيل تلاوات تدريبية من هاتفه وإرسالها للمعلم.

### المستخدمون

| الدور | ماذا يفعل في التطبيق |
|---|---|
| **المدير (admin)** | ينشئ حسابات المعلمين والطلاب، ويدير الحلقات |
| **المعلم (teacher)** | يرفع تلاوات طلابه من الاستوديو، يكتب ملاحظات، يراجع تدريبات الطلاب |
| **الطالب (student)** | يسمع تلاواته ويقرأ الملاحظات، يسجّل تدريبات ويرسلها |

لا يوجد تسجيل ذاتي (sign up). كل الحسابات ينشئها المدير أو المعلم، والدخول باسم مستخدم وكلمة سر.

### الاستوديو الحالي

التسجيل الرسمي يتم في الاستوديو عبر ميكسر Midas (يُدار ببرنامج M-AIR-Edit) وبرنامج Studio One 7. التطبيق **لا يتصل بهذه البرامج مباشرة**. المعلم يصدّر الملفات من Studio One ويرفعها للتطبيق عبر صفحة الرفع الجماعي في نسخة الويب.

## 3. نموذج البيانات (العقد المشترك بين الثلاثة)

> هذا القسم هو "العقد" بيننا. أي تعديل عليه يُناقش مع الفريق أولاً، لأن الكل يعتمد عليه.

```
users/{uid}
  username: string            // "s023"
  fullName: string
  role: "admin" | "teacher" | "student"
  studentCode: string?        // "S023" للطلاب فقط
  halaqaId: string?           // للطلاب فقط
  fcmTokens: string[]         // لأجهزة الإشعارات
  createdAt: timestamp
  disabled: bool              // الحساب موقوف؟ (الافتراضي false، يغيّره السيرفر فقط)

users/{uid}/progress/{surahNumber}     // متابعة الحفظ (المرحلة الثانية)
  status: "in_progress" | "memorized"
  updatedBy: string
  updatedAt: timestamp

halaqat/{halaqaId}
  name: string                // "حلقة الفجر"
  teacherId: string

recordings/{recordingId}
  studentId: string
  halaqaId: string            // مكرر عمداً لتسهيل الاستعلام والحماية
  teacherId: string           // مكرر عمداً
  uploadedBy: string
  type: "official" | "practice"
  surahNumber: int            // 1..114
  ayahFrom: int
  ayahTo: int
  storagePath: string         // "recordings/{studentId}/{id}.mp3"
  durationSec: int?
  recordedAt: timestamp
  createdAt: timestamp
  unreadFeedback: bool        // للطالب: هل في ملاحظة جديدة؟
  reviewed: bool              // للمعلم: هل راجع التدريب؟

recordings/{recordingId}/feedback/{feedbackId}
  teacherId: string
  note: string
  atSecond: int?              // ملاحظة على لحظة معيّنة من التلاوة
  rating: int?                // 1..5
  createdAt: timestamp
```

### قواعد ثابتة

- **الأدوار** تُخزَّن كـ Custom Claim (`role`) في الحساب، ولا يضعها إلا كود السيرفر.
- **اسم المستخدم** يتحوّل داخلياً لإيميل: `s023` ← `s023@afdal-uloom.app`.
- **في قاعدة البيانات نخزّن مسار الملف فقط** (`storagePath`) وليس رابطاً كاملاً.
- **الواجهة لا تتعامل مع Firestore مباشرة أبداً**، بل عبر الـ Repositories في `lib/core/`.
- **السورة تُخزَّن برقمها** (2 = البقرة)، واسمها يُعرض من قائمة ثابتة داخل التطبيق.

### تسمية ملفات الاستوديو

```
{رقم الطالب}_{التاريخ}_{رقم السورة}_{من آية}-{إلى آية}.mp3
S023_2026-10-05_002_1-20.mp3
```

استخدمنا رقم السورة بدل اسمها العربي لتجنّب مشاكل الأحرف العربية في أسماء الملفات بين البرامج.
إعدادات التصدير: **MP3، Mono، 64 kbps**.

> المدة تقديرية وتعتمد على وقت الفريق. الأهم هو الترتيب: **لا ننتقل لأسبوع 7 قبل نجاح التجربة الأولى**.

### نقطة مهمة: كيف نشتغل بالتوازي من أول أسبوع؟

محمد ونور يعتمدان على كود شادي (Models وRepositories). حتى لا ينتظرا:

1. شادي يسلّم في **الأسبوع الأول** الـ Models والـ Interfaces فقط، مع **نسخ وهمية (Fakes)** ترجع بيانات تجريبية ثابتة.
2. محمد ونور يبنيان الشاشات على الـ Fakes.
3. في **الأسبوع الرابع** يستبدل شادي الـ Fakes بالنسخ الحقيقية المتصلة بـ Firebase، وتشتغل الشاشات دون تعديل لأنها تعتمد على الـ Interface نفسه.

## 6. طريقة العمل على Git

### الفروع

```
main          ← الفرع الدائم الوحيد: آخر نسخة مدمجة وشغّالة
feature/...   ← كل مهمة في فرع مستقل يبدأ من main
```

أمثلة: `feature/shadi-login`، `feature/mohammed-bulk-upload`، `feature/nour-audio-player`

فرع `develop` لم يعد مستخدماً: لا تبدأ منه ولا ترسل إليه Pull Request.

### القواعد

1. **قبل كل مهمة** ابدأ من آخر نسخة من `main`:
   ```bash
   git checkout main && git pull
   git checkout -b feature/<اسمك>-<الموضوع>
   ```
2. **لا أحد يكتب على `main` مباشرة.** كل شيء عبر Pull Request إلى `main`.
3. **كل PR يراجعه شخص واحد على الأقل** غير صاحبه، والدمج إلى `main` بقرار شادي.
4. **الإصدارات** علامات (tags) على `main`: `v0.1.0`، `v0.2.0`، ...
5. **رسائل الـ commit** صغيرة ومنطقية، بهذا الشكل:
   - `feat: إضافة شاشة الرفع الجماعي`
   - `fix: إصلاح القفز للثانية في المشغّل`
   - `refactor:` / `test:` / `docs:` / `chore:` / `build:`
6. **أضف الملفات بأسمائها** في الـ commit، وليس `git add .`، حتى لا يدخل ملف بالخطأ.
7. **ممنوع رفع أي مفتاح سري**: ملفات `serviceAccountKey.json` وأي `.env` موجودة في `.gitignore`.
8. **اسحب آخر نسخة من `main` يومياً** (`git pull`) وادمجها في فرعك لتقليل التعارضات.

## 7. معنى "انتهت المهمة" (Definition of Done)

المهمة لا تُعتبر منتهية إلا إذا:

- [ ] تعمل على Android والويب (وiOS إذا توفر جهاز Mac)
- [ ] لا توجد تحذيرات من `flutter analyze`
- [ ] الواجهة تتعامل مع الـ Repositories فقط، لا مع Firestore مباشرة
- [ ] الشاشة سليمة بالعربي واتجاه RTL، وتعمل على شاشة هاتف صغيرة
- [ ] حالات التحميل والخطأ والقائمة الفارغة معالجة (ليست شاشة بيضاء)
- [ ] تمت مراجعة الـ PR ودمجه في `main`

## 8. التواصل

- **اجتماع قصير أسبوعي**: كل واحد يقول ماذا أنجز، وماذا سيعمل، وهل هو عالق في شيء.
- **أي تعديل على نموذج البيانات** (القسم 3) يُناقش قبل تنفيذه.
- **صلاحيات Firebase**: شادي يضيف محمد ونور كأعضاء في المشروع (Editor). الفوترة عند شادي فقط.
- **الخصوصية**: التطبيق يحفظ أصوات طلاب قد يكونون أطفالاً. لا أحد ينزّل تسجيلات حقيقية على جهازه الشخصي أو يشاركها خارج التطبيق.
